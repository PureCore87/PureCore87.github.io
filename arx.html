Two areas / One vault

A place for what you keep private.

01 / Credentials

Your accounts, organised.

Create and edit entries containing a title, username, password, website and notes. Keep them in the encrypted vault and choose when to reveal or use them.

02 / Files

A familiar way to organise.

Use folders and subfolders, a directory tree, list/tile/detail views, sorting and file properties. Rename, copy, move and delete content, with back/forward folder history during your session.

03 / Android Autofill

Confirm what you share.

Use selected credentials in supported apps and web forms through Android Autofill. Unlock the vault, choose an entry and confirm the receiving app or website before releasing it.

04 / Local control

No required ARX account.

The documented app has no internet permission and does not require an ARX server or cloud account. You choose exports, sharing actions and the storage provider used for backups.

Use your content thoughtfully

Organise. Read. Transfer with care.

05 / Text

Read private text inside ARX.

Open supported text files in the internal read-only viewer, with wrapped lines and paged display for longer content. This includes the protected Logins.txt produced by a backup import.

06 / Media

View supported images and videos.

Use integrated image viewing and video playback for supported content. Available formats depend on Android decoders, and an Android default app can handle some media opening actions.

07 / Import & export

Verify the destination first.

When moving content into or out of the vault, ARX writes the destination and fully reads it back for verification before removing the source. Unconfirmed steps are reported.

08 / Explicit sharing

You choose the recipient.

Opening with another app, exporting a file, using Autofill or copying credentials deliberately releases readable information. The encrypted copy inside the vault and the released copy are different things.

  1. WriteSave the selected content at its destination.
  2. Read backCheck the complete stored destination content.
  3. Remove sourceOnly after successful verification; report incomplete moves.

An exported file is readable at its destination. If a provider cannot remove an imported source, the original can remain outside the vault. Ordinary deletion is not a promise of forensic erasure.

Backups / Restore / Import

A backup that is read back.

09 / Encrypted backups

Credentials, files and folders together.

Create a new encrypted .arxb backup at a location you select. ARX reopens and fully verifies the stored backup before reporting success; existing backups are kept.

10 / Full restore

Start again on a suitable device.

Restore a complete backup into an installation without an existing vault. The current process needs the backup file, its password and a supported device; it does not require a separate exported backup key file.

11 / Additive import

Keep the vault you already use.

Import backup contents into a new folder in Files. Existing content, structured credentials and the current master password are retained. Imported credentials are placed in an encrypted Logins.txt rather than automatically merged into Credentials.

12 / Password changes

A new password for the current vault.

Change the master password after verifying the existing one. Stored content stays in place. Older backups still require the passwords used when they were created, so create a new backup after changing your password.

Protection with a clear explanation

Several measures, working together.

ARX Core combines Argon2id password-based key derivation, AES-256-GCM authenticated encryption and a hardware-protected Android Keystore key for the local vault. Its own keyboard handles sensitive inputs, while protected windows and session locking complement access control.

How local access is protected

A randomly generated data key protects vault content. Password-derived protection and the device’s hardware-backed Keystore protect access to that key. StrongBox is preferred when available; a suitable trusted execution environment can also be used. Software-only or unknown security levels are rejected by the documented implementation.

The master password has a 16–128 character rule. Screen locking ends the vault session; a normal short background switch has a 60-second grace period. Android file-picking and external-opening flows have their own return rules.

Android 14 or later is required, together with compatible hardware-backed Keystore support. Device compatibility is still being tested. An independent security review has not been completed.

Before you put something private inside

Questions about ARX Core.

What if I forget my master password?

There is no developer access or password reset that bypasses encryption. A backup also needs its own password. Without the required access information, your data can become permanently inaccessible.

Do older backups use my new master password?

No. A backup keeps the password it was created with. Changing the current vault’s master password does not rewrite, delete or revoke previously copied backups.

Does importing a backup replace my vault?

The additive import creates a new folder inside Files and keeps the existing vault and its password. Full restoration is a separate process intended for an installation without an existing vault.

Why does a backup import create Logins.txt?

Imported backup credentials are represented as text inside an encrypted vault file, instead of being automatically merged into the current Credentials list. The internal text viewer reads that file locally. Exporting or sharing it releases readable credentials.

Does ARX always keep every file inside its own viewer?

No. There is an internal text viewer and support for viewing certain images and videos. Some media can open in an Android default app, and other document types can require an external app. An explicit Open with action gives the selected app readable access.

Are original files removed immediately during import?

ARX first verifies the stored vault destination. Source removal happens afterwards. If source deletion is unavailable or cannot be confirmed, ARX reports that the move is incomplete; a readable original may still exist outside the vault.

Does ARX require a cloud service?

No ARX account or required ARX cloud service is part of the documented vault workflow. You can still deliberately select a document provider that uses your own cloud storage for a backup or export.

Is ARX Core available to download?

ARX Core is in active development. Core vault functions are implemented, while broader device testing, independent security review and release preparation remain. A public download or purchase link will be added when confirmed.
